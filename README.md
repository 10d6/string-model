# String Model

A physically modelled bowed string instrument (violin and cello; viola and
bass to follow), built on [synthkit](https://github.com/10d6/synthkit). It
runs in the browser and as a VST3 / AU plugin.

It is polyphonic: every note is a waveguide string of its own, bowed through
a thermal friction model (Woodhouse's, with the 2025 Woodhouse–Galluzzo
refinement for attacks), up to 16 at once, all on one bridge and body, with
the four open strings ringing in sympathy. A gesture layer turns keys into
bow speed, force and position, and plays like a musician: expressive
intonation, vibrato by context. Legato (Mono) turns it into one violinist
who slurs, shifts and slides. The physics follows
[10d6/instrument-research](https://github.com/10d6/instrument-research).
How it works: [docs/MODEL.md](docs/MODEL.md). Roadmap: [docs/PLAN.md](docs/PLAN.md).

## Playing it from a keyboard

| | |
|---|---|
| Velocity | how hard the note starts, and its dynamic |
| Mod wheel / CC 11 | dynamics (bow speed and distance from the bridge together) |
| Aftertouch | bow pressure: airy ↔ crunchy |
| CC 74 | contact point: sul tasto ↔ sul ponticello |
| Pitch bend | the fingers slide (±2 semitones) |
| Keys | polyphonic: each key a note with its own string and bow, up to 16; chords sound in full |
| Overlapping keys, Legato (Mono) on | slur (same bow) within Slur Range: a finger change, or a shift if the note is out of the hand's reach; separate keys change bow; velocity sets the shift's speed |
| Key-up speed | Release Auto: a quick release stops the bow on the string, a gentle one lifts it |
| C1, C#1, D1, D#1, E1 | keyswitches: string Auto, G, D, A, E (sul G, sul D…) |
| F1, F#1, G1, G#1, A1, A#1, B1 | keyswitches: articulation Arco, Martelé, Spiccato, Tremolo, Pizzicato, Harmonics, Sautillé |

### Articulations

| | |
|---|---|
| Arco | the normal bowed sound: everything above |
| Martelé | the bow pinches, then a fast accented stroke that stops on the string |
| Spiccato | the bow is thrown and bounces off: short, light notes |
| Tremolo | fast bow changes on one note (Tremolo Rate, ~12 per second) |
| Sautillé | the bow bounces by itself: fast repeated notes, its speed set by how fast you play |
| Pizzicato | plucked, with a long ringing tail; key-up as with the bow (a quick release damps it with the hand) |
| Harmonics | flageolet: a natural harmonic if the note has one, else an artificial one (stopped note + a touch a fourth, a fifth or an octave above); the pure, glassy tone of the recordings |

### The player and the body

| Control | |
|---|---|
| Intonation Style (Left Hand) | equal temperament ↔ expressive: open strings in pure fifths, leading tones higher |
| Vibrato Shaping (Left Hand) | vibrato by context: wider up high, narrower in fast runs, growing on long notes |
| Portamento (Left Hand) | Legato: audible slides on slow slurred leaps: the player keeps such leaps on one string and slides (0: clean shifts, string crossings) |
| Avoid Open Strings (Left Hand) | in slower playing with vibrato, D4, A4 and E5 are stopped on the string below so they can vibrate, as players do; fast passages use the open strings |
| Attack Swell (Bow) | bowed notes grow into their level as the Philharmonia player's do, most at soft dynamics |
| Air Resonance, Nasality, Brilliance, Softness, Voice (Body) | the violin's character, as offsets from the measured instrument; presets *Cremonese, Dark & Vocal*, *Cremonese, Bright & Vocal*, *Modern Soloist*, *Student Factory Violin* |

## Playing it

- **In the browser:** every PR gets a preview link (posted on the PR), and
  `main` is at the repo's GitHub Pages site. This needs GitHub Pages turned
  on once: Settings → Pages → Deploy from a branch → `gh-pages` / root.
- **In your DAW:** plugin builds are off for PRs (they're slow). To get
  them, run CI by hand (Actions → CI → Run workflow, "plugins" ticked) and
  download **plugin-windows**, **plugin-macos** or **plugin-linux** from that
  run's Artifacts, or tag a version (`v0.2.0`), which publishes a release.
  Unzip and follow `INSTALL.md` inside.

## Building

```
git clone --recursive <this repo>
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build build
./build/stringmodel_render --check . --out renders     # every check; WAVs into renders/
```

The browser page and the plugins are built the same way as in synthkit: see
[`synthkit/API.md`](synthkit/API.md) §11–12.

## Layout

| | |
|---|---|
| `synth.json` | identity (name, IDs, plugin codes) and kit features |
| `model/` | the physical model (plain C++, no synthkit): string, friction, gesture layer, instrument data |
| `src/` | the synth: parameters, events, output stage; `src/ir/` is generated by `tools/gen_ir.py` |
| `data/` | CC0 library-mic impulse responses and the radiation target (derived from VSCO-2-CE, via instrument-research). The recordings themselves (VSCO, the Philharmonia samples) are never committed: see CLAUDE.md |
| `tools/` | offline labs (`string_lab`, `instrument_lab`, `radiation_lab`, `performer_fuzz`), calibration and evaluation scripts against the recordings (`perceptual.py`, `partial_q.py`, `brightness_spread.py`, …); CLAUDE.md lists every command |
| `docs/` | `MODEL.md` (how it works), `PLAN.md` (roadmap, ideas), `EVALUATION.md` (how to check it, reference numbers, lessons) |
| `presets/` | factory presets (`init.json` is what a new instance starts on) |
| `tests/` | render scenarios checked in CI |
| `ui/layout.json` | the panel layout (and `ui/custom.js` for custom widgets, `ui/style.css` for styles, or `ui/page.js` for a page of the synth's own: API.md §9a) |
| `synthkit/` | the kit, as a pinned submodule |
